Security Model

The design goal is simple: shrink the attack surface until there is nothing valuable to attack.

  • Content Security Policy Every page ships a strict CSP meta tag: scripts only from same origin or two vetted cdnjs libraries, no inline scripts, no eval-style injection paths, object-src 'none', frame-ancestors 'none' to defeat clickjacking.
  • No exfiltration channel connect-src 'self' means the browser refuses any fetch/XHR/WebSocket to other origins. Malicious injected code still cannot phone home.
  • Ephemeral state Clinical answers exist only in a JavaScript object in RAM. There is no at-rest data to steal from disk, and no session tokens or credentials anywhere in the system.
  • Minimal supply chain Runtime dependencies are limited to jsPDF and AutoTable from cdnjs, pinned by URL with integrity-verifiable versioned paths. All other logic is first-party vanilla JS.
  • Static hosting With no server-side code, databases, or admin panels, there is no remote infrastructure to compromise — the deployment surface is a set of read-only files.
  • Input handling All rendered content goes through DOM APIs (textContent), not innerHTML interpolation, so responses typed by users cannot become script.
  • Auditable changes Clinical logic lives in one data file; every modification is a version-controlled commit attributable to a reviewer.
  • Residual risks Trust still depends on your browser, the hosting provider, and TLS certificate issuance. Use up-to-date browsers and verify the site's origin before answering.
